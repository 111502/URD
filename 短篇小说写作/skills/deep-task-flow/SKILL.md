# Deep Task Flow 深度任务执行框架 v1.1

通过"理解→预演→计划→执行→检查"的闭环确保高质量输出。

## 流程总览

```
0. 复杂度判断 → 完整流程 / 快速通道
        ↓
1. 需求澄清（逐问至95%信心）→ 用户确认
        ↓
2. 错误预演（3-4个关键风险）→ 用户确认/补充
        ↓
3. 计划制定 + 角色设定 + 展示模式 → 用户确认
        ↓
4. 执行
        ↓
5. 检查（结论优先 → 细节可选）
        ↓
   通过 → 交付 / 不通过 → 迭代修正
```

## Phase 0: 复杂度判断

| 完整流程 | 快速通道 |
|----------|----------|
| 多步骤/多维度 | 单一明确操作 |
| 质量要求高 | 常规标准化任务 |
| 失败风险大 | 容错空间大 |
| 用户要求深度执行 | 用户要求快速完成 |

### 快速通道流程

```
1. 一句话确认需求："你需要的是[X]，对吗？"
2. 直接执行
3. 简单检查：核心目标是否达成
4. 交付
```

## Phase 1: 需求澄清

**核心原则**：一次只问一个问题，根据回答追问，直到95%信心。

**必须探测的维度**：
- 核心目标：真正想达成什么
- 约束条件：篇幅、时间、风格、格式
- 使用场景：给谁看、什么情境
- 成功标准：怎么判断"做得好"
- 输出形式：文档/口头、大纲/完整、单方案/多备选

**结束标志**：用一段话复述需求，获得用户确认。

## Phase 2: 错误预演

在动手前具象化失败场景。**只列3-4个最关键的风险点**。

**两层预演**：
1. 通用层：这类任务的常见坑
2. 具体层：这个特定任务的独特风险

**输出格式**：
```
关键风险点：
1. [风险] → 预防：[做法]
2. [风险] → 预防：[做法]
3. [风险] → 预防：[做法]

是否认同？您还担心什么？
```

## Phase 3: 计划制定 + 角色设定

**计划制定**：拆解为可执行步骤，每步明确输出物。

**专家角色选择**：

| 维度 | 选择逻辑 |
|------|----------|
| 任务类型 | 写作→资深编辑；分析→行业分析师；技术→资深工程师 |
| 受众 | 专业人士→领域专家；普通读者→科普作家 |
| 质量要求 | 快速草稿→高效执行者；精雕细琢→完美主义者 |

**展示模式确认**（v1.1新增）：
```
执行过程展示偏好：
A. 完整模式：展示思考过程和中间产物（适合想学习思路）
B. 精简模式：只展示最终结果（适合只要结果）
```

获得用户确认后进入执行。

## Phase 4: 执行

以设定的专家角色执行计划，按用户选择的模式展示过程。

## Phase 5: 检查

**Step 1: 结论优先**
```
检查结论：✓ 通过 / ✗ 需迭代

[如用户想看细节，再展开各维度评估]
```

**Step 2: 锚定核心**
- 这个任务的核心成功标准是什么？
- 核心必须100%达标

**Step 3: 多维审视**
- 检查角色：与执行角色形成对抗（如执行是"创意总监"，检查是"挑剔的读者"）
- 按优先级检查，非核心维度可接受妥协

**Step 4: 迭代（如需要）**
- 定位问题属于哪个环节 → 回到该环节修正 → 重新检查
- 迭代上限：3轮

## 用户确认节点

- [ ] 需求澄清后：确认理解准确
- [ ] 错误预演后：确认风险点、补充担忧
- [ ] 计划制定后：确认方案+展示模式

## Graceful 降级（v1.1新增）

当用户中途表示"太麻烦了"/"直接做吧"：

```
收到，切换到快速模式。

基于目前了解到的信息，我理解你需要[X]。
现在直接执行，完成后做简单检查。

[直接进入执行]
```

**降级原则**：
- 不质疑用户选择
- 用已收集的信息继续
- 保留简单检查环节
- 交付时说明"如需调整随时告诉我"
